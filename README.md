# 전략적 자산배분 멀티에이전트 파이프라인

> **가상 데이터로 만든 학술 프로젝트입니다.**
> KAIST 디지털금융MBA 현장적용프로젝트 산출물이며, 실제 운용 자료가 아닙니다.
> 화면에 등장하는 수치와 이사회 보고서는 전부 임의로 생성한 예시입니다.

LLM 에이전트가 자본시장 가정을 산출하고, 22개 방법론으로 포트폴리오를 구성한 뒤
상호 검토와 위험 심사를 거쳐 결합하는 파이프라인입니다. 투자정책서(IPS)가
전 과정을 통제합니다.

**[→ 설계 목업 보기](https://kujae.github.io/saa-agents/)**
· [설치 및 실행 안내](docs/SETUP.md)

## 확정된 설계 결정

**결합 방식** — 하나를 선택하지 않고 7개 방법론을 가중 결합합니다. 제안서 원문과
같습니다. 결합하면 "왜 이렇게 배분했나"를 설명하기 어려워지는데, 자산군별 기여
분해로 해결했습니다.

**순위 투표** — 1위표만 세지 않고 전 후보에 순위를 매겨 보르다로 집계합니다.
호불호가 갈리는 후보와 두루 인정받는 후보를 구분하기 위해서입니다.

**토론 3라운드 상한** — challenger가 반박하면 지목된 자산군만 재추정합니다.
전량 재실행 대비 비용이 크게 줄어듭니다. 상한에 걸려도 미해결 반박을 버리지 않고
해당 자산군의 확신도를 낮춥니다. 수렴하지 못했다는 사실 자체가 정보이기 때문입니다.

**위험관리 에이전트** — 제안서 4단계에 명시된 구성요소인데 초기 설계에서
빠져 있어 추가했습니다. 투표와 독립적으로 각 후보를 심사합니다.

**하이브리드 경계** — LLM 에이전트 7종, 결정론적 함수 6종, 하이브리드 1종입니다.
`optimizers`와 `cov_estimator`는 LLM을 전혀 호출하지 않습니다. 원 논문이
전부 "에이전트"라고 부른 것을 구분해 명시한 것이 이 프로젝트의 설계 기여입니다.

## 팀에서 정해야 할 것

**1. `saa/prompts.py` 8개 함수 담당 배정**

파일 하나만 열면 됩니다. 코드는 볼 필요 없고, `# TODO` 부분을 도메인 지식으로
채우면 됩니다. mock 모드에서는 비어 있어도 파이프라인이 계속 돕니다.

| 함수 | 채울 내용 | 담당 |
|---|---|---|
| `macro()` | 국면 판정 기준, 지표 우선순위 | |
| `asset_view()` | 방법론 적용 순서, **확신도 산정 근거** | |
| `challenge()` | 어떤 모순을 반박할 것인가 | |
| `revise()` | 수용과 방어의 판단 기준 | |
| `critique()` | 방법론 간 비판 관점 | |
| `ranking()` | 순위 부여 기준 | |
| `risk_note()` | 결정적으로 볼 위험 지표 | |
| `board_memo()` | 보고서 구성과 어조 | |

`asset_view()`가 가장 중요합니다. 토큰의 절반 이상을 쓰고, 여기서 나오는
확신도가 Black-Litterman의 이탈 폭을 직접 결정합니다.

**2. IPS 제7조 제2항 부채 듀레이션을 범위에 넣을지**

현재 파이프라인에 미구현 상태입니다. 넣으면 목적함수가 자산 수익률에서
적립비율로 바뀌어 프로젝트 성격이 달라집니다.

**3. 결합 가중치 산식**

현재는 `보르다 점수 × 위험계수`입니다. 위험조정성과 기반 등 다른 방식도 가능합니다.

**4. 투표의 독립성**

21개 에이전트가 같은 기반 모델을 쓰면 판단이 상관됩니다. 다수결이 독립적
검증이 아니라 같은 편향의 증폭일 수 있습니다. 에이전트별로 다른 모델을 쓰거나
의도적으로 반대 입장을 부여하는 설계가 필요한지 결정해야 합니다.

## 룩어헤드 문제

이 프로젝트의 가장 큰 함정입니다.

에이전트에게 "2020년 3월 기준으로 판단하라"고 시켜도, LLM은 그 이후 무슨 일이
일어났는지 이미 학습했습니다. 데이터 파이프라인을 아무리 깨끗이 짜도 모델
가중치 안에 미래가 들어 있습니다.

제안서 연구내용 1번이 백테스트 검증이므로, **백테스트가 오염되면 주된 주장이
통째로 무너집니다.** 그래서 두 가지 장치를 넣었습니다.

**데이터 계층 차단** — `market.py`가 실현 수익률을 갖고 있고, 도구는 `as_of`
이전만 잘라서 줍니다. 에이전트는 미래 수익률에 물리적으로 접근할 수 없습니다.

**구간 분리** — 성과를 학습 컷오프 기준 전후로 나눕니다. 두 구간의 성과 차이가
곧 룩어헤드의 크기입니다. 이전 구간에서만 초과성과가 나고 이후에 사라지면
실력이 아니라 기억이었다는 뜻입니다.

검증 하네스는 자체 검증이 됩니다. `SIMULATE_LEAKAGE=1`로 누출을 심으면
컷오프 이전 초과수익이 +3.70%p로 뛰고 이후는 +0.07%p에 머물러 정확히 잡아냅니다.
